# v4.0 M4 日志系统优化（广泛插桩）实现计划

> **给执行者：** 必用子技能：superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐任务实现。步骤用复选框跟踪。

**目标：** 让终端日志显示大部分**中间结果、关键数据流转、关键步骤**——用户运行时能看到每步的输入/输出数量、每条 source→sink 路径、每个 gate 决策、每个融合分组与打分、每个进化决策。

**架构：** 复用 `tracing` 的分层（stderr 终端 / `log_file` 文件）。当前 `tracing::info!` 已默认打到 stderr，但**各模块内部几乎不 emit**，只有 pipeline 打概要——所以核心动作是「在源码里广泛插桩」。终端走 INFO/DEBUG，文件走 TRACE；关键数据流转用一行式 `source → … → sink(category)` 打印。同时把新模块的 scope target 补进 CLI 的 `SCOPE_TARGETS`。

**技术栈：** Rust（edition 2024），`tracing`，workspace crate `mcp-sec-audit-{core,cli}`。

**规格：** `rust/docs/v4.0/IDEA_EVALUATION_AND_DESIGN.md`（§八 日志系统优化，含 8.4 插桩清单与 8.5 可视化示例）。

## 全局约束

- Rust edition **2024**；不加外部依赖。
- `tracing` target 沿用 `mcp_sec_audit::*`；新增 `::facts`、`::infer`、`::evolution`（`::diff`/`::validate`/`::component` 已在 M1 建立）。
- 终端可见的中间结果用 `tracing::info!`（或 pipeline 里的 `progress()`）；细粒度排查用 `tracing::debug!`/`trace!`。
- 关键数据流转一律一行式：`source:... → ... → sink:...(category)`。
- 不改变任何分析逻辑——只加日志语句。
