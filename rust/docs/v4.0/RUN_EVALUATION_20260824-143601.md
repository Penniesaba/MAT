- **P0 修复闭环验证生效**：CLI 2.26.3 + 单语言 MaD pack 隔离后致命错误消失；excel 2 条命中即 CVE 本体（`workbook.py:23/66`，数据流 `get_excel_path → full_path → load_workbook`），与 taint 线对价吻合。
- **MCTS 多语言**：Python+JS 出 5 条全真实（path-traversal / file-write / tool-param-to-sink），`executionSuccessful=True`、无 exitCode 异常。

**暴露两处新问题**（见 §四）：

1. **Rust 提取有 `database-quality` 告警** —— "Scanning Rust code completed successfully, but the scan encountered issues"，伴随大量 `data-flow-consistency-counts` / `ssa-consistency-counts` 诊断（Rust extractor macro caveat）。Rust 线出 **0 条结果**，不是没漏洞，是 Rust 线基本失效。
2. **`codeql_raw_sarif` 字段是 3 份 SARIF 直接拼接成的一个字符串**（`schema` 出现 3 次），对下游是非法 JSON（`json.loads` 报 `Extra data`）。

### 2.2 Agent —— ⭐ 最强线，语义质量超预期

MCTS 15 条 finding（全 High/Medium），质量分层清晰：

**高价值真阳性（其他三线漏掉）：**
- `run_shell` 里 `shell=True` 命令注入（`subprocess.check_output(command, shell=True)`）
- `get_env` 任意环境变量读取 → 凭据泄露（点明 `OPENAI_API_KEY`）
- SSRF + 数据外带 via `notify_webhook`
- Tool poisoning（`list_files` 声明只读却写盘）

**进化线里 Agent 的 L3 裁决尤其亮眼**（`ambiguous_for_review` 两条）：

- `main.rs:10 run_tool` —— 正确判定"**不是 shell 注入**（`Command::new` 直接 exec 二进制、无 `.args()`），且 `run_tool` 从未被 `call_tool` 调用，是**为静态发现而存在的 fixture，不暴露可达路径**"。
- `server.ts:22 read_config` —— 正确判定为"**完全可达**的任意文件读取"。

这是真正的语义推理（区分 reachable/unreachable、shell injection vs arbitrary exec），非模式匹配。

**代价**：非确定性（excel 上 4→3，`preview_only 外带` 这条 High 消失）；少量低价值噪声（`capability over-exposure`、`context over-sharing PII`，Medium 且带 advisory 属性）。

### 2.3 进化 —— ⚠️ 闭环跑通，但"真进化"尚未兑现

进化机制（两阶段差分 + promote/rollback）端到端跑通，标签产出正确：

```
Migration: b1=0 a1=0 a2=2 b2=0 b0=4 still_ambiguous=2
Decision: promoted staged models to learned
```

**b0 候选质量高**（4 条全真实 sink）：`subprocess.check_output`(command_execution/high)、`open`(file_write/medium)、`requests.post`(network_request/high)、`std::process::Command::new`(command_execution/high)。

**三个硬伤让"进化效果"目前是空的：**

1. **`promoted` 字段语义误导 + 实际是 no-op**（`pipeline.rs:532`）：`promoted: !rolled_back`，而 `should_rollback()` 是 `b2 > b1`（`validate.rs:38`）。MCTS 里 `b2=0 b1=0` → 永不回退 → 永远"promoted"。**且 MCTS config 未配 `learned_dir`**，`promote()` 压根没执行，日志却报 `promoted staged models to learned` —— 报告进化成功但实际什么都没写。
2. **b0 是 "surfaced for human review"，不是自动持久化** —— 4 条候选都只是摆出来等人工，循环没闭环到自动学习。
3. **已持久化的 learned 模型价值存疑**（`rust/models/learned/` 仅 4 个文件，全来自 excel 目标，MCTS 一个没写）：
   - 多为 `confidence: low`，且基本复述 sink catalog 已有条目（`openpyxl.load_workbook`、`Workbook.save`、`FastMCP.tool`）。
   - `openpyxl.load_workbook → file_read` 这类"库专用名当 sink"的建模方式泛化性差。
   - **`open → file_write` 候选若持久化会是大坑**：`open()` 读/写/追加由 mode 决定，裸 `open` 当 file_write sink 会爆炸性误报（本次证据 `open(path,"w")` 恰好是写，但规则本身太宽）。

**结论**：进化管线"形似闭环"，差分标签、b0 候选、Agent 裁决三者都对，但"学习"这一环没有产生实际检测能力提升 —— 目前本质是"高质量的人类评审辅助器"，不是自主进化器。

## 四、不足与改进建议（按优先级）

### 已确认、应立即修（低成本高收益）

| # | 问题 | 证据 | 修法 |
|---|---|---|---|
| **P1-A** | `delete` 前缀 → `file_delete` 误报 | excel 11 条 `delete_range/delete_worksheet/...` 参数全被判文件删除 | `infer.rs::NAME_PREFIX_CATEGORY` 删 `("delete","file_delete")`（真删文件动词已在 `sinks/python.toml:152`），加回归测试；`remove` 同构风险一并观察 |
| **P1-B** | `file_read`/`file_write` 双向过计数 | excel 170 条 taint 绝大多数是同一参数 × (读+写) 两报，如 `copy_range:sheet_name → file_read` 且 → file_write | taint 结果层按 `(source, sink_category, 位置)` 去重 / 读+写归一为 `file_modify` |
| **P1-C** | `promoted` 语义误导 / no-op | `pipeline.rs:532` 用 `!rolled_back`；MCTS 无 `learned_dir` 却报 "promoted" | `promoted` 改为"实际写了几条模型"，空 delta 时明确报 "nothing to promote" |

### 需设计确认（中风险，先讨论）

| # | 问题 | 证据 | 方向 |
|---|---|---|---|
| **P2-A** | Fusion 跨文件聚合不兑现 | 同一 CVE 拆成 4 条（`workbook.py`/`__main__.py`/`server.py`/agent 无定位），因 `matcher.rs` 两阶段都要求 `file_key` 相等 | 引入"漏洞签名"（sink 函数名如 `get_excel_path`/`load_workbook`）或"类别族"（path_traversal↔file_read）作跨文件聚合键；**有过度合并风险，需拍板** |
