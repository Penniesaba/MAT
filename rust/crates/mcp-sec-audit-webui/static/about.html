mcp-sec-audit

把 MCP 服务器安全审计，从命令行带到桌面。

一个配置、运行、监控三位一体的 Web 控制台。静态与动态混合分析，规则、污点、CodeQL、Agent 四条线融合打分，产出可复核的 fused findings。

开始使用

它是什么

mcp-sec-audit 是面向 MCP（Model Context Protocol）服务器的安全审计工具。它把「纯 CLI + 冗余日志」升级为「配置 → 运行 → 监控」的可视化工作流，CLI 与 Web 并行共存，不取代后者。

静态分析

多语言事实提取（Python AST、JS/TS tree-sitter、Rust），构建调用图，从 sink 反向 BFS 做轻量污点分析，再经规则匹配、CodeQL 与 Agent 语义分析。

动态分析

Docker 沙箱加 eBPF 系统调用监控，捕获运行时行为作为静态分析的补充。v6 沿用开关，不在前端控制。

相关性融合

四条分析线（rule / taint / codeql / agent）结果融合打分，多线一致时加权，最终产出融合后的 findings 与风险定级。

四条分析线

每条线回答不同的问题，融合后互为印证。

规则引擎

确定性模式匹配，覆盖 MCP 与多语言规则目录，速度快、结果可审计。

污点分析

从 sink 反向 BFS 的轻量污点传播，追踪不可信数据到达危险汇点的路径。

CodeQL

数据库驱动的语义查询，覆盖跨文件数据流，适合深层的代码模式缺陷。

Agent 语义分析

用 LLM 复核候选 findings，结合上下文做语义判断，降低误报。

分析管线

每个仓库走一遍「两阶段 × 两线」的结构，进度条粒度由此而来。

Setup
Discover→ LoadRulebook→ LoadCatalog→ BaselineComponents
Phase 1
Rule→ Taint→ CodeQL→ Agent
Evolution
GateG1G2→ StageG3→ Diff1
Phase 2
Taint₂→ CodeQL₂→ Agent₂ ←rule 复用不重跑
Validation
Diff2→ Migrate→ Explain→ Adjudicate→ Promote
Finish
Fusion→ Partition→ Report

为什么用 Web 版

把运维动作可视化，而不是盯着终端里滚动的日志。

配置 → 运行 → 监控

页面上填好配置（或导入现成 TOML），一键启动批量或单仓库分析，实时查看每个仓库的进度与分层日志。

批量并行

一次并行分析多个仓库，进度条纵向排列，点开任意一个即可看到它的运行细节。

本地运行

Web 进程内调用 core，不 spawn CLI 子进程、不解析 stdout，结构化事件经 WebSocket 推送。
